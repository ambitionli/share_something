# AEB Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a C++17/ROS2-oriented AEB demo that receives 30 Hz all-I-frame H.264 over UDP, decodes it on NVIDIA Orin, evaluates a simple image-based AEB rule, and outputs a brake decision.

**Architecture:** The project follows an Apollo-inspired module layout: common data types, transport, decoder, algorithm, node integration, tools, tests, and docs are separated by responsibility. The testable core library has no ROS2 or GStreamer dependency; Orin hardware decoding and ROS2 publishing are optional build targets enabled on the deployment platform.

**Tech Stack:** C++17, CMake, Linux sockets, optional GStreamer `nvv4l2decoder`, optional ROS2 `rclcpp`.

---

## File Structure

- `include/aeb_demo/common/`: frame, decision, status, and latest-frame buffer types.
- `include/aeb_demo/algorithm/`: AEB algorithm interface and simple ROI-based implementation.
- `include/aeb_demo/transport/`: UDP packet protocol, H.264 Annex-B parser, receiver interfaces.
- `include/aeb_demo/decoder/`: decoder interface and GStreamer hardware decoder declaration.
- `include/aeb_demo/node/`: ROS2 node-facing orchestration types.
- `src/`: implementation files mirroring `include/`.
- `tools/`: debug H.264 UDP sender.
- `tests/`: standalone C++ tests using `assert`, built with CTest.
- `doc_auto/`: implementation record required by workspace rules.
