## 2. 用户流程

- [x] 登录：手机号格式校验 + `login_phone`；微信 `getUserProfile` + `login_wechat`。
- [x] 启动：`session` 自动同步 openid 与用户文档。
- [x] 首页：分类筛选、关键词过滤、Banner、商家列表。
- [x] 商家/购物车：加减数量、备注、金额展示。
- [x] 结算：地址选择（列表页 pick）、`order_create` + `order_pay`（模拟）。
- [x] 订单列表/详情：状态展示、支付/取消/退款申请、跳转评价。
- [x] 评价：星级、文字、图片上传云存储后提交 `review_create`。

## 3. 商家流程

- [x] 入驻：`merchant_register` + 资质图上传。
- [x] 工作台：`merchant_my`、`stats_merchant`。
- [x] 商品：`merchant_product_upsert`。
- [x] 订单：接单/拒单（库存回滚）、配送完成、退款处理（库存回滚）。

## 4. 逻辑与安全（云函数）

- [x] 合并重复商品行后再算价与校验库存（`mergeItems` + `buildOrderCents`）。
- [x] 支付前事务内重算金额与库存，防止篡改价格。
- [x] 拒单与同意退款退回库存与销量。
- [x] Node 测试：`npm test` 通过。

## 5. 已知限制（非阻塞）

- 支付为模拟，非微信真实支付。
- 优惠券为前端演示数据，未与订单核销联动。
- 列表部分使用内存排序，数据量大时需在控制台加索引或改查询。

## 结论

自检项全部通过，可作为可导入微信开发者工具的基线版本；上线前需配置真实 AppID、云环境权限、支付与客服等生产能力。
